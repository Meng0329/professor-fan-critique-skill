# 九维评审参考 — 详细说明

## 设计背景

本评审框架源自两次组会中樊老师对开题报告和PPT的锐评（第一次组会 + 开题答辩）。樊老师的评审风格具有以下特征：

1. **问题驱动**：始终追问"解决什么问题"，而非"用了什么技术"
2. **证据主义**：每个claim都要有出处，每个创新都要查证prior art
3. **底线思维**：预判审稿人会从哪里攻击，提前堵漏
4. **领域嵌入**：评审者必须具备领域常识，不能外行评内行
5. **名实相符**：题目和内容必须匹配，不能"题大实小"
6. **量→质叙事转换**：不是做了多少工作，而是带来了什么知识转变
7. **问题→数据对应**：每个研究问题必须有对应的数据源支撑

## 核心原则详解（源自第一次组会）

### 原则一：问题驱动，而非技术驱动

**背景**：第一次组会明确要求"以问题为导向，而非以技术为导向"——技术内容应放到最后，不要以技术选型驱动研究框架。

樊老师的判断标准：
- 如果开篇第一段在讲技术栈（LLaMA、Eino、Neo4j）→ 技术驱动 ❌
- 如果开篇第一段在讲问题（条件缺失、模型幻觉、质控空白）→ 问题驱动 ✅

**评审检查**：去掉所有技术名词后，研究框架是否仍然成立？如果成立，说明是问题驱动。

### 原则二：从"量的变化"到"知识的变化"

**背景**：第一次组会特别强调——"量的变化没有创新点"。开题报告不能通过"我处理了多少数据"来论证价值。

樊老师的判断标准：
- "我采集了20万篇文献" → 量的变化，不是创新点
- "我构建了条件感知的知识表征方法" → 知识的变化，可能是创新点
- 创新点必须落脚在知识形态的转变，而非数据规模的增长

**评审技巧**：把作者说"我做了X"替换为"我带来了什么知识转变"——如果替换后逻辑不通，说明叙事有问题。

### 原则三：抽取→质检→应用闭环

**背景**：第一次组会定义了核心流程：抽取 → 质检 → 应用。缺少任何一个环节都是不完整的研究。

樊老师的判断标准：
- 只做抽取不做质检：数据不可信
- 只做质检不做应用：价值未验证
- 只做应用不做溯源：结论不可信
- 三者缺一不可，且环节之间必须有明确的接口

### 原则四：问题→数据对应

**背景**：第一次组会强调"问题与数据需对应"——每个研究问题都需要对应的数据源。

樊老师的判断标准：
- 每个提出的问题都要追问："数据在哪？"
- 如果问题提得很好但没有数据支撑 → 不成立
- 数据源的质量和局限性必须与问题的重要性相匹配

### 原则五：可解释性与专家判断

**背景**：第一次组会强调"可解释性与专家判断"——学术研究不能是黑箱。

樊老师的判断标准：
- AI/LLM方法的每一步决策都要能追溯到输入
- 必须有专家介入的接口（人机协同验证）
- 不可解释的方法等于不存在

## 维度详解

### 一、题目聚焦度

樊老师原话：*"你题目写这么大，做不完怎么办？"*

这个维度的核心是**题目与产出之间的匹配度**。学位论文的题目是审稿专家最先看到的内容，也是最先被攻击的点。

常见问题模式：
- 题目涵盖整个领域（"面向分子育种"），但实际只做了一两个抗性
- 题目写的是战略报告级别的范围，但产出只是一个原型系统
- 题目用了"面向XX"这种大范围表述，但没有次级限定

**送审风险**：如果题目写"面向分子育种"，但专家发现你没有做任何湿实验、没有品种对比、没有田间验证，就会质疑你"名实不符"。

**改进策略**：要么缩小题目（如"面向水稻耐热性分子育种"），要么在题目中明确产出类型（如"基于文献知识图谱的水稻基因-性状关系挖掘方法研究"）。

### 二、文献基础对比

樊老师原话：*"国内外都在做，你凭什么说你是新的？"*

这个维度要求**全面梳理已有工作并明确差异**。不是简单罗列"张三做了A，李四做了B"，而是要有比较、有分析、有判断。

**关键追问**：第二次组会上樊老师特别指出——"你创新点第一条就提这个事，好像没人做过——但我看到之前他们汇报的文件里，大家不都在说吗？"

必须对比的系统（以水稻分子育种知识挖掘为例）：
- RiceScientist（多智能体水稻科学家的相关研究）
- CDLM / CLM（条件语言模型、作物文献挖掘相关工作）
- 龙虾助手/ABC（其他农业知识挖掘工具）
- CMM/Be半（1400万篇文献，技术方案也做微调）
- 各大学（中国农大、南京农大等）和科研机构（中科院遗传所等）的相关工作
- **神经符号方法（Neuro-symbolic）** 的相关工作——if-then规则集成与知识图谱推理的大量已有研究

**学科圈定**：第一次组会要求"明确学科问题圈定"——你需要说明你的综述覆盖了哪些研究社区、排除了哪些。不能让人觉得你对领域全貌不了解。

**改进策略**：制作一张对比表，列出现有系统在数据规模、技术路线、评估方式、覆盖范围等方面的差异，用表格说明"别人做到了什么、还有什么没做好"。特别是把那些看起来相似的工作列出来，然后说明你的独特差异。

### 三、创新点真实性

樊老师原话：*"你说'首次'，你敢确定吗？"*

这个维度检验**创新点的真实新颖性**。论文评审中最容易被攻击的就是创新点——专家会集中精力验证"你说的创新到底是不是真的创新"。

风险信号：
- "首次"、"首个"等绝对化表述往往会在prior art审查中被推翻
- 把已有概念换个名字就当作创新（如"条件感知" vs "基因-环境互作"）
- 把技术实现方案的不同当作问题创新
- 把"现有方法做得不好"等同于"没人做过"

**改进策略**：在宣称创新前，先进行系统的文献检索。如果确实有类似工作，坦诚说明差异点——"虽然XX等人也做了YY工作，但他们没有考虑ZZ，因此我们的贡献是……"

### 四、数据深度分析

樊老师原话：*"你报了20万篇，然后呢？"*

这个维度衡量**对数据本身的理解程度**。仅仅报告采集了多少数据是不够的，需要展示你对数据的深入分析。

**关键追问**：量（20万篇）→ 质（你从数据里发现了什么知识）是叙事转换的核心。第一次组会明确：量的变化没有创新点。第二次组会更具体：你要按品种分类、按籼稻/粳稻分类、评估与育种实践的相关性。

必须展示的分析：
- 品种分布（籼稻多少、粳稻多少、其他多少，按大分类先分清楚）
- 年代分布（文献的时间覆盖范围）
- 质量分布（预印本占比、期刊来源分布、可信度分级）
- 品种-性状覆盖矩阵（哪些品种在哪些性状上有数据）
- **真值标定分析**：私有材料不可获取的情况下，如何标定ground truth？
- **品种与品种的关联分析**：同一品种在不同文献中的出现频次、描述一致性

**常见错误**：只计划了"将来要做什么分析"，没有展示"已经对数据做了什么分析"。开题的评估依据是你已有的工作，不是你未来的计划。

**改进策略**：在开题报告/论文中增加独立的数据分析章节或小节，用图表展示数据的多维分布情况。在开题阶段就要让人感觉"你对这批数据已经摸透了"。

### 五、领域知识深度

樊老师原话：*"你懂水稻育种吗？"*

这个维度检验**对应用领域的理解深度**。如果系统声称面向分子育种但作者对育种基本知识不了解，专家会直接否定整个研究。

**关键追问**：第二次组会上樊老师专门指出——"北方的水稻是做耐寒的，你说它有耐热的基因，这就不对。" 品种背景与性状的对应关系是领域知识的底线要求。

基础知识要求：
- 水稻品种分类（籼稻/粳稻/其他，以及主要栽培品种的籼粳分类）
- 系谱/血缘关系（父本、母本、传代历史——育种家最看重这个）
- 不同品种的适种区域和主要性状（北方耐寒、南方耐热）
- 育种目标与品种匹配（不同育种目标需要不同的品种背景）
- **基因→表型核心链条**：每个基因要能关联到一个可测量的表型，并在品种背景下验证

**时空对齐**：同一个基因在不同环境条件和发育阶段的表现可能完全不同。你是否考虑了这种时空动态？

**改进策略**：在论文中增加水稻领域基础知识的介绍，展示你对品种分类和系谱的理解。在知识图谱设计中纳入品种背景信息。特别要展示你知道"不同品种的同一基因不能直接类比"。

### 六、权威知识库整合

樊老师原话：*"光有文献够吗？权威数据库呢？"*

这个维度要求**整合权威数据源作为ground truth**。仅靠文献抽取的知识做推理是不可靠的，必须有权威数据库作为校验基准。

关键数据源：
- NCBI（基因注释、序列数据）
- IRRI（国际水稻所，品种数据）
- UniProt（蛋白质功能注释）
- KEGG（通路数据）
- RiceVarMap（水稻变异图谱）
- 各基因组所的基因编号体系

**改进策略**：在系统设计中明确说明整合了哪些权威数据库，以及它们如何作为知识图谱的校验基准。

### 七、命名体系与对齐

樊老师原话：*"同一个东西不同数据库叫法不一样，你怎么办？"*

这个维度识别**实体对齐的技术挑战**。不同数据库、不同文献对同一基因/品种的命名可能完全不同。

**关键追问**：第二次组会上樊老师说——"你去看看国际水稻所IRRI、咱们农科院、NCBI、北京基因组所——每家都有自己的库，光ID标注就很多种表达方法。光这个对齐就能做一篇研究论文了。"

存在的命名差异：
- IRRI vs NCBI vs 农科院 vs 北京基因组所——每家都有自己的编号体系
- 不同文献可能使用不同的基因命名惯例
- 品种名的异名（同一品种在不同语境下可能有不同叫法）
- 国际协作中的竞争关系（各方希望自己的命名体系成为主流）
- **时空对齐问题**：同一实体在不同时间点的文献中可能被不同地标注或描述
- **多源语义冲突**：不同研究社区对同一概念的定义可能不同

**关键认识**：这不是一个"可以顺便做掉"的事情。樊老师明确说这本身就能发一篇研究论文。必须严肃对待，不能轻描淡写。

**改进策略**：将实体对齐作为独立的研究任务，明确对齐方案、难度评估和预期效果。不要轻描淡写地带过。如果技术方案中没有对齐步骤，或者只说"用NLP实体匹配解决"，那就是轻视了这个问题的难度。

### 八、可行性验证

樊老师原话：*"你说能辅助决策，怎么证明？"*

这个维度要求**提供可验证的系统有效性证据**。空谈"辅助决策"但没有验证方案，专家不会认可。

验证策略：
- **复现验证**：选一篇已发表的水稻育种论文，用系统复现其数据分析流程
- **基准测试**：用已知的基因-性状关系检验系统的知识召回率和准确率
- **消融实验**：验证每个模块的独立贡献
- **专家评估**（备选）：请育种专家评估系统输出质量

**改进策略**：在开题/论文中设计一个明确的验证章节，包括复现实验的设计方案。

### 九、送审风险预判

樊老师原话：*"审稿专家是搞这个的，他会怎么怼你？"*

这个维度进行**防御性评审**——站在审稿人角度找出最可能的攻击点。

常见风险点：
- 题目过大、落地不足的结构性矛盾
- 缺乏实验验证（干实验和湿实验之间的鸿沟）
- 与已有工作差异不明确
- 数据质量无法保证
- 核心概念定义不清晰

**改进策略**：在论文中增加独立的"局限性与未来工作"章节，坦诚说明每个方法/数据的局限性。预判审稿人的问题并提前回应。

## 评审哲学

樊老师的评审哲学可以用一句话概括：

**"你凭什么说这个话？"**

每一项claim都需要证据支撑：
- 你说问题重要？→ 请引用顶刊证明
- 你说你的方法新？→ 请对比所有已有工作
- 你说你能辅助决策？→ 请用实验证明
- 你说你考虑了条件？→ 请展示你懂领域知识

在学术评审中，**没有证据的claim就是弱点**。好的研究不是没有问题，而是坦诚面对问题并有应对方案。
