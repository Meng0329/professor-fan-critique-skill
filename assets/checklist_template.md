# 樊老师九维自检清单

**用途**：在提交开题报告、学位论文、PPT或任何学术提案前，逐项自检。

**使用方法**：逐条核对，标记 ✔（满足）/ ✘（不满足）/ △（部分满足）。任一维度有3个以上✘则必须修改。

---

## 核心原则自检（来自第一次组会）

### 原则一：问题驱动
- [ ] 开篇第一段在讲问题而非技术栈
- [ ] 去掉所有技术名词后，研究框架仍然成立
- [ ] 技术方案被放在问题陈述之后

### 原则二：量→质叙事
- [ ] 创新点落脚在知识形态的转变，而非数据规模
- [ ] 不是用"我处理了多少数据"来论证价值
- [ ] 每个创新点都能回答"带来了什么知识转变"

### 原则三：闭环完整
- [ ] 覆盖抽取→质检→应用三个环节
- [ ] 每个环节之间有明确的接口定义
- [ ] 没有缺少任何一个环节

### 原则四：问题→数据对应
- [ ] 每个研究问题都有对应的数据源
- [ ] 数据源的局限性与问题的严重性匹配
- [ ] 没有"问题很好但数据支撑不了"的情况

### 原则五：可解释性
- [ ] 方法每一步都能追溯到输入
- [ ] 有专家介入/人机协同的接口
- [ ] 不是端到端黑箱

## 一、题目聚焦度

**核心追问**：你题目写这么大，做不完怎么办？

- [ ] 题目范围聚焦到1-2个具体问题/性状，而非"面向XX领域"
- [ ] 领域专家看一眼题目就知道具体做什么
- [ ] 题目承诺的内容与实际产出匹配
- [ ] 不存在"题目写战略报告，实际做系统"的落差
- [ ] 题目有次级限定词缩小范围

## 二、文献基础对比

**核心追问**：国内外都在做，你凭什么说你是新的？

- [ ] 已梳理全部同类系统（RiceScientist, CDLM, 龙虾助手等）
- [ ] 有对比表格（方法/数据规模/技术/评估）
- [ ] 明确说明"别人做了什么→做到什么程度→还有什么没做好"
- [ ] 核心claim有顶刊文献背书
- [ ] 引用了Nature Genetics / Molecular Plant / PBJ等期刊

## 三、创新点真实性

**核心追问**：你说"首次"，你敢确定吗？？

- [ ] 每个创新点都做了prior art检索
- [ ] 没有滥用"首次"、"首个"等绝对化表述
- [ ] 如果已有类似工作，差异点足够显著
- [ ] 创新是问题层面的突破（而非技术组装）
- [ ] 区分了"现有方法不够好"和"没人做过"
